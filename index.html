BEFORE사기 전에, 최악의 경우부터 보여주는 미국주식 리스크 서비스

2026.03 – 06 · 16주5인 팀기획 · 백엔드 리드토스 미니앱 정식 출시

증권 앱은 모두 "얼마나 오를까"만 말합니다. 초보 투자자에게 필요한 건 "최악이면 얼마나 떨어지나"라고 보고, 30일 하방 시나리오와 그 이유를 쉬운 한국어로 보여주는 서비스를 만들었습니다.

문제 정의

상승 예측 대신 하방 리스크를 먼저

  • 기존 증권 서비스는 목표가·상승률 중심이라 손실 규모를 알려주지 않음
  • 모델이 결과만 주면 "왜 위험한지" 알 수 없음 → 초보자는 믿지 못함
  • 출시 전 랜딩페이지로 수요를 먼저 검증: 방문 286명 중 122명 사전예약

AI를 어떻게 붙였나

숫자는 모델이, 설명은 LLM이

  • TFT 모델이 30일 분위수 경로와 최악 손실률을 계산, XAI로 영향 변수 Top-3 추출
  • Upstage Solar LLM이 Top-3를 3단 한국어 해설로 풀어 씀 (프롬프트 v11까지 개선)
  • LLM에는 사실 묶음만 주고 숫자를 못 바꾸게 함. "매수·추천·보장" 금칙어 검증, 실패 시 템플릿으로 대체 (자본시장법 대응)

내가 한 일

핵심 기능이 부가 기능 때문에 멈추지 않게

  • LLM 타임아웃이 뒤따르는 위험 알림 발송까지 막는 문제를 발견 → 알림 단계를 분리해 항상 실행되게 하고, LLM 호출은 병렬화
  • 인증(JWT 회전)·회원·워치리스트·요청 제한 API 11개, 테스트 53개 작성
  • GitHub Actions 매일 새벽 파이프라인, 위험 등급 변화 푸시 알림(FCM) 구현

항상 실행위험 등급 변화 감지→푸시 알림 · FCM

파이프라인 전체 6m39s → 2m9s. LLM이 실패해도 알림 발송은 100% 보장되도록 단계를 격리. LLM은 사용자 요청 경로에서 호출하지 않아 응답 지연 없음.

제품 판단

틀리게 잇느니 안 잇는다

  • 다른 아이에게 기록이 붙으면 되돌릴 수 없는 개인정보 사고 → 정밀도 최우선
  • 애매한 건 "확인 필요" 큐로 보내 교사가 처리, 승인된 기록만 저장·공유 (Human Gate 2단계)
  • 1차 목표를 기능 개수가 아닌 입력부터 공유까지 끊기지 않는 흐름으로 설정

AI를 어떻게 붙였나

LLM은 애매할 때만 부른다

  • LangGraph로 추출 → 후보 좁히기 → (조건부) LLM 판정 → 결정 그래프 설계
  • 이름이 명확하면 LLM을 건너뜀 → 정확도와 비용 모두 개선
  • 임베딩은 비슷한 이름을 가깝게 봐서 동명이인에서 틀림 → 매칭엔 쓰지 않음

평가를 의심하기

96%가 나왔을 때 더 따져봤다

  • 모델의 자기보고 confidence가 두 번 실행 시 같았던 비율 44.5% → 임계값 대신 규칙 판정으로 전환
  • 3줄짜리 단순 기준선이 100%를 받는 걸 보고 평가셋 결함 발견 → 기준선 채점 도구 제작
  • 튜닝 데이터에 섞인 holdout을 분리 (dev 665 / holdout 405)
기록 한 건이 부모에게 닿기까지
기관 기록 업로드→ 매칭 에이전트→ 검증 에이전트→ 요약→ 교사 승인→ 아동별 통합 기록→ 인사이트→ 발송 승인→ 부모 공유

매칭 에이전트는 제가 주 개발자(매칭 코드 커밋 11개 중 10개). 검증 에이전트는 전화번호·주민번호를 정규식으로 항상 차단해 모델 호출이 실패해도 규칙이 지켜집니다. 원본은 기관 밖으로 나가지 않고, 부모가 동의한 범위만 공유됩니다.
